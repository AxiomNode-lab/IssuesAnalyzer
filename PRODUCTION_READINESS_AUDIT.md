Audit date: 2026-09-03  
Baseline: `origin/main` at `a7547316570ec13ee1377302989921f1cd3985d8`

This matrix records the repository-wide audit completed before implementation work began. The
review covered workspace/package manifests, lockfile policy, Next.js configuration and bundled
version-matched guidance, API routes, OAuth/session handling, GitHub integration, URL validation,
database schema and access code, caches, rate limiting, scoring/analyzer packages, UI rendering,
tests, CI, operational scripts, environment templates, and architecture/security/operations docs.

## Controls verified as already effective

- The issue URL parser accepts only canonical HTTPS `github.com/{owner}/{repo}/issues/{positive-integer}` URLs, rejects credentials, ports, queries, fragments, encoded/ambiguous paths, lookalike hosts, and constructs all GitHub API paths from validated identifiers. The GitHub REST client uses a fixed API origin and `redirect: "error"`; no arbitrary server-side URL fetch was found.
- The analyze route requires JSON, streams into a 4 KiB bound, returns safe errors, and does not expose stack traces. SQL calls use tagged-template parameterization and ownership is derived from the signed server session.
- Public analysis cache keys are canonical, case-normalized, and explicitly public; user/session data is not stored in that cache. Same-issue cold requests are already single-flighted within one process and stale evidence is eligible for fallback on transient GitHub failure.
- Evidence pagination and collection are bounded (comments, timeline, pull requests, commits, releases, and historical issue sample). Scoring logic is deterministic and evidence-backed. No scoring or viewport behavior change is required by this audit.
- React renders evidence as text; no `dangerouslySetInnerHTML` usage was found. New-tab links use `rel="noreferrer"`, and no `NEXT_PUBLIC` secret references were found.
- The repository ignores `.env` variants except `.env.example`. A source scan found no real tokens, credentials, or private keys; only deliberate redaction-test fixtures matched token patterns.
- CI uses a frozen lockfile, pinned Node/pnpm versions, immutable action SHAs, PostgreSQL integration, operational shell syntax checks, and a production dependency audit. The production dependency audit reported no registry-known vulnerabilities on 2026-09-03.
- PostgreSQL has ownership/uniqueness/check constraints, relevant saved/report/evidence/job/audit indexes, transactions for account deletion, and a module-level pool rather than a pool per request. Backup output uses restrictive permissions and validates the archive.

## Deferred or infrastructure-owned risks

- Cross-instance single-flight and shared evidence caching require a shared cache/coordination backend. This PR will provide clean interfaces and Redis-compatible deployment guidance, while preserving no-Redis local development; instance-local coalescing remains the fallback.
- Removing `'unsafe-inline'` from production script CSP safely requires a nonce or supported SRI deployment design and end-to-end browser verification. It is not safe to delete the allowance blindly.
- Metrics/logs must be exported by the hosting platform for global aggregation, retention, alerting, and tracing. The repository can emit structured events but cannot select or deploy the operator's monitoring vendor.
- Backup encryption, retention, off-site storage, production restore authorization, and rollback execution remain platform/operator responsibilities.
